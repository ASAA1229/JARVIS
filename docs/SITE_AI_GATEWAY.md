# JARVIS Personal AI Gateway for Websites

JARVIS can be the AI provider for your websites — the portfolio today and any
future site — instead of a paid cloud API. Answers are generated by the local
model JARVIS is configured with (default: Ollama `llama3.2` on this laptop).

## How it works

```
Visitor ─▶ Website server (e.g. portfolio /api/chat)
             │  Authorization: Bearer jrv_… (server-side secret)
             ▼
        HTTPS tunnel (Cloudflare Tunnel)  ──▶  JARVIS site gateway 127.0.0.1:<port>/v1
                                                     │
                                                     ▼
                                             local model (Ollama)
```

- **OpenAI-compatible:** `POST /v1/chat/completions` (streaming and non-streaming),
  `GET /v1/models`, `GET /v1/health`. Any OpenAI SDK works with `baseURL` set to
  the gateway and the site key as `apiKey`.
- **Separate listener:** the gateway runs on its own port, so a tunnel can expose
  `/v1` without exposing the device/owner API, HUD or enrollment routes.
- **Text only:** site keys cannot reach the planner, policy gateway, personal memory,
  device actions or tools. `tools`, `functions` and `response_format` are refused.
- **Per-site keys:** stored only as SHA-256 hashes, shown once, revocable instantly,
  each with its own requests-per-minute and max-output-token limits.
- **Audited:** every request records site, status, sizes and duration in the
  tamper-evident audit log — never prompts or generated text.

## Set up (once)

1. Install the local model: `ollama pull llama3.2`
2. In JARVIS `.env`, set `JARVIS_SITE_GATEWAY_PORT=3100`.
3. Create a key per site: `npm run site-key -- create portfolio`
   (options: `--rpm 20 --max-tokens 800`). Copy the printed key; it is not shown again.
4. Start JARVIS: `npm start` — you should see
   `JARVIS site AI gateway is listening on http://127.0.0.1:3100/v1`.
5. Check locally:
   ```
   curl http://127.0.0.1:3100/v1/health
   curl http://127.0.0.1:3100/v1/chat/completions \
     -H "Authorization: Bearer <key>" -H "Content-Type: application/json" \
     -d '{"messages":[{"role":"user","content":"Say hello"}]}'
   ```

## Expose it to a deployed site

A site hosted on the internet (Cloudflare Workers, Vercel, …) cannot reach
`127.0.0.1`. Publish **only the gateway port** through an HTTPS tunnel, for
example Cloudflare Tunnel (`cloudflared` is free):

```
cloudflared tunnel --url http://127.0.0.1:3100            # quick test URL
# or a named tunnel on your own domain, e.g. ai.<your-domain> → http://127.0.0.1:3100
```

Never point a tunnel at the main JARVIS port (`PORT`, default 3000).
When the laptop is off or asleep the site gets a 502/503 and should fall back
(the portfolio shows its offline, profile-grounded answers).

## Connect a website

Server-side environment (never in browser code):

```
JARVIS_AI_URL=https://ai.<your-domain>
JARVIS_AI_KEY=jrv_…
```

The portfolio reads these in `src/lib/ai-provider.ts` and prefers JARVIS over
OpenAI automatically. For any other site:

```ts
import OpenAI from "openai";
const jarvis = new OpenAI({ baseURL: process.env.JARVIS_AI_URL + "/v1", apiKey: process.env.JARVIS_AI_KEY });
const reply = await jarvis.chat.completions.create({
  model: "jarvis",
  messages: [{ role: "system", content: "You answer questions about this site." }, { role: "user", content: "Hi" }],
});
```

## Operate

- List keys: `npm run site-key -- list`
- Revoke a leaked key: `npm run site-key -- revoke portfolio` (takes effect on the next request; no restart)
- Rotate: revoke, create a new key with the same name, update the site secret.
- Limits: 64 KiB request body, 40 messages, 48,000 input characters, 2 concurrent
  requests per site and 4 overall (the local model is shared).
